# Audio Input

&emsp;&emsp;The audio-input (AI) module captures audio data, which can then be sent to AENC for encoding.

&emsp;&emsp;The AI module supports different devices on different platforms.

| **Chip family** | **ADC** | **PDM** | **I2S0** | **I2S1** |
| ----------- | ------- | ------- | -------- | -------- |
| KM02G series | Supported | Supported | Not currently supported | Not currently supported |

<br/>

## Multi-Microphone DTS Configuration

To switch among one-, two-, and multi-microphone configurations where the hardware supports them, edit the corresponding DTS, rebuild the DTB, and flash it.

1. Enter `os/kernel/arch/riscv/boot/dts/anyka`, select the applicable DTS, and find `&adc_dac {...};`.

### 1. Configure One ADC Microphone

Set `mic-info = <MIC_INFO_ADC_MIC0>`.

```dts
pinctrl-0 = <&speaker_en_pins>;
```

### 2. Configure Two ADC Microphones

```dts
pinctrl-0 = <&speaker_en_pins>;
```

Set `mic-info = <(MIC_INFO_ADC_MIC0|MIC_INFO_ADC_MIC1)>`.

Single-microphone mode currently opens left `mic0`; using right `mic1` alone is not supported.

### 3. Configure Two PDM Microphones

Set `pinctrl-0 = <&speaker_en_pins>,<&pdm_pins>;`.

Set `mic-info = <(MIC_INFO_PDM0|MIC_INFO_PDM1)>;`.

Also enable the following `dev3` configuration:

```dts
dev3 {
    snd-dev = <SND_CARD_PDM_RECV>;
    snd-type = <AK_PCM_DEV_CAPTURE>;
};
```

### 4. Configure Four PDM Microphones

Set `pinctrl-0 = <&speaker_en_pins>,<&pdm_pins>;`.

Set `mic-info = <(MIC_INFO_PDM0|MIC_INFO_PDM1|MIC_INFO_PDM2|MIC_INFO_PDM3)>;`.

Also enable the following `dev3` configuration:

```dts
dev3 {
    snd-dev = <SND_CARD_PDM_RECV>;
    snd-type = <AK_PCM_DEV_CAPTURE>;
};
```

## Multi-Device, Multi-Channel Parameter Matrix

The following matrix describes the supported multi-device, multi-channel cases:

| Input condition | DevId | SrcCnt | Chn Cnt | Sound mode | `get frame` output |
| ----------------------- | ----- | ------ | -------- | -------------- | --------------------------------------------------------------------- |
| Mono ADC | ADC0 | 1 | 1 | MONO | Outputs mono data |
| Two microphones, not an array (same controller) | ADC0 | 2 | 2 | MONO | Use `get frame(ch0)` and `get frame(ch1)` to obtain the two outputs separately |
| Two-microphone array, raw data only, without noise reduction | ADC0 | 2 | 1 | MONO | Outputs the two microphones interleaved in one channel |
| Two-microphone array with multi-microphone noise reduction | ADC0 | 2 | 1 | MONO | Outputs mono data |
| Two microphones capturing stereo | ADC0 | 2 | 1 | STEREO (not currently supported) | Outputs two-channel stereo data |
| Four microphones, not an array (same controller) | ADC0 | 4 | 4 | MONO | Use `get frame(ch0)` through `get frame(ch3)` to obtain four outputs separately |
| Four microphones capturing stereo | ADC0 | 4 | 1 | Four-channel stereo (not currently supported) | Outputs four-channel surround stereo |
| Two microphones, not an array | PDM0 | 2 | 2 | MONO | Use `get frame(ch0)` and `get frame(ch1)` to obtain two outputs separately |
| Two-microphone array with multi-microphone noise reduction | PDM0 | 2 | 1 | MONO | Outputs mono data |
| Two microphones capturing stereo | PDM0 | 2 | 1 | STEREO (not currently supported) | Outputs two-channel stereo data |
| Four microphones, not an array | PDM0 | 4 | 4 | MONO | Obtain four outputs separately |
| Four-microphone array with multi-microphone noise reduction | PDM0 | 4 | 1 | MONO | Outputs mono data |

## AI Noise-Reduction Configuration
### Modify audio_config.ini
1. Enable the following options in `audio_config.ini` and update the model path, for example:
```c
aidenoiseEna=1
modelName="/tmp/nfs/model_aidenoise"
numFrameDescriptor=2
```

2. AI noise reduction conflicts with conventional noise reduction, so disable NR and AGC after enabling AI noise reduction.

### Modify the Kernel DTS
Apply the following kernel-DTS configuration:
```c
#define RESERVED_NPU_RUN_SIZE 0x2000000 // 16MB
#define RESERVED_ION_BASE     0x43408000
#define RESERVED_CMA_BASE     0x4a408000
```

```{warning}
The supplied source pairs `0x2000000` with the comment `16MB`; those do not describe the same byte count. Both tokens are retained verbatim here. Confirm the intended reserved-memory size with Anyka before changing or deploying this configuration.
```

### Application Changes
Add `AK_MPI_NPU_Init` and `AK_MPI_NPU_Deinit` to the application.
Link `akAIdenoise`, `ak_nne`, and `plat_npu` in the application Makefile.
Call `AK_MPI_AUDIO_RegisterAIDenoise()` to register AI noise reduction.

### Load the Drivers
Before running the application, load the drivers with these commands. Set `path=/tmp/nfs/` to the model-storage path.
```bash
insmod /lib/modules/5.10.111/kernel/drivers/base/firmware_loader/firmware_class.ko path=/tmp/nfs/
insmod /usr/modules/ak_npu.ko
```

### **AUDIO_DRV_BUF_TYPE_E**

&emsp;&emsp;【Description】

&emsp;&emsp;Audio-capture driver-buffer type. When configuring an AI, AO, or Loopback driver buffer, use an `AUDIO_DRV_BUF_TYPE_E` value to identify the buffer.

## User-Defined Algorithm Interface

### AK_MPI_AI_EnableAecRefFrame

&emsp;&emsp;【Description】

&emsp;&emsp;Configures the Loopback data required by this channel. Call it only before `AK_MPI_AI_EnableChn`. After configuring frames for echo cancellation, no audio-effect parameters (NR, AGC, AEC, EQ, ASLC, and so on) or digital-gain amplification can be used. This interface is currently unavailable.

After configuring echo-cancellation reference frames, the AI and Loopback data returned by `AK_MPI_AI_GetFrame` is stored in an interleaved layout.

| Category | Data layout |
| ------------------------------ | ------------------------------------------------------------------------- |
| Captured data is mono | \|Loopback\|Chn1\|Loopback\|Ch1\|...... |
| Captured data has two channels; channel 1 requires Loopback data | \|Loopback1\|Chn1\|Ch2\|Loopback1\|Ch1\|Ch2\|...... |
| Captured data has two channels; both require Loopback data | \|Loopback1\|Loopback2\|Chn1\|Ch2\|Loopback1\|Loopback2\|Ch1\|Ch2\|...... |
| Captured data has four channels; all four require Loopback data | \|Loopback1\|Loopback2\|Loopback3\|Loopback4\|Chn1\|Ch2\|Ch3\|Ch4\|..... |

## Volume Settings

### **AK_MPI_AI_SetGain**

&emsp;&emsp;【Description】

&emsp;&emsp;Adjusts analog volume. Microphone analog-gain behavior for each use case is described below:

| Use case | Gain behavior |
| -------------------------------------------------- | ---------------- |
| Single microphone; `u32SrcCnt = 1` in `AK_MPI_AI_SetPubAttr` | The corresponding microphone's capture gain can be adjusted independently |
| Multiple microphones used independently; `u32SrcCnt = 2` or `4` in `AK_MPI_AI_SetPubAttr` | Each microphone's capture gain can be adjusted independently |
| Multi-microphone array; `u32SrcCnt = 1` in `AK_MPI_AI_SetPubAttr` | All microphones use the same gain |

PDM does not support analog-volume configuration; this call fails for a PDM device.

## Performance-Tuning Interfaces

### AK_MPI_AI_SetDrvBufPeriods

&emsp;&emsp;【Description】

&emsp;&emsp;Adjusts the number of audio-data buffer blocks used by the capture and echo-cancellation drivers. Total driver-buffer size is the buffer-block size multiplied by the block count. `Periods` is the block count; its default is 8. Increase it when heavy system load prevents audio data from being retrieved promptly.

【Syntax】

```c
    AK_S32 AK_MPI_AI_SetDrvBufPeriods(AK_S32 s32AiDevId,
                                      AUDIO_DRV_BUF_TYPE_E enDrvBufType,
                                      AK_U32 u32Periods);
```

&emsp;&emsp;【Parameters】

| **Parameter** | **Description** | **Value range** | **Input/Output** |
| ------------ | ----------------- | ----------------------- | --------- |
| s32AiDevId | audio-input module device ID | See AUDIO_AI_DEV_ID_E | Input |
| enDrvBufType | Audio-driver buffer type | See `AUDIO_DRV_BUF_TYPE_E` | Input |
| u32Periods | Number of audio-driver buffer blocks | [8,80], in multiples of 8; default: 8 | Input |

&emsp;&emsp;【Return Values】

| **Return value** | **Description** |
| ------- | ------ |
| 0 | Success |
| Other | See the error codes |

&emsp;&emsp;【Error Codes】

| **Error code** | **Description** |
| ---------------------- | ------ |
| ERROR_TYPE_INVALID_ARG | invalid parameter |

&emsp;&emsp;【Requirements】

&emsp;&emsp;Libraries: libplat_ai.so or libplat_ai.a

&emsp;&emsp;Header: ak_ai.h

&emsp;&emsp;【Call Sequence】

```c
    /* Step 1: Configure common device attributes */
    AK_S32 s32AiDevId = DEV_ADC0;
    AUDIO_IN_PARAM_S pstParam = {0};
    pstParam.enSampleRate = AK_AUDIO_SAMPLE_RATE_8000;
    pstParam.enSampleBits = AK_AUDIO_SMPLE_BIT_16;
    pstParam.enSoundMode = AUDIO_SOUND_MODE_MONO;
    pstParam.u32SrcCnt = 1;
    pstParam.u32ChnCnt = 1;

    // configure ADCattribute
    pstParam.stAdcConfig.enSourceType = AUDIO_ADC_SOURCE_MIC;
    pstParam.stAdcConfig.sReserved = 0;

    AK_S32 ret = AK_MPI_AI_SetPubAttr(s32AiDevId, &pstParam);
    if (ret) {
        return ERROR;
    }

    AUDIO_IN_PARAM_S attr;
    memset(&attr, 0x0, sizeof(attr));
    ret = AK_IMP_AI_GetPubAttr(s32AiDevId, &attr);
    if (ret) {
        return ERROR;
    }

    /* Step 2: Enable the AI device */
    ret = AK_MPI_AI_Enable(s32AiDevId);
    if (ret) {
        return ERROR;
    }

    /* Step 3: set driver buffer/internalthread priority */
    AK_S32 s32AiChnId = 0;
    AK_U32 u32AiPeriods = 16;
    AK_U32 u32LoopbackPeriods = 16;
    AK_S32 s32AiPeriods = 80;
    AK_S32 s32LoopbackPeriods = 80;
    ret = AK_MPI_AI_SetDrvBufPeriods(s32AiDevId, AUDIO_DRV_BUF_AI, u32AiPeriods);
    if (ret) {
        return ERROR;
    }
    ret = AK_MPI_AI_GetDrvBufPeriods(s32AiDevId, AUDIO_DRV_BUF_AI, &u32AiPeriods);
    if (ret) {
        return ERROR;
    }

    ret = AK_MPI_AI_SetDrvBufPeriods(s32AiDevId, AUDIO_DRV_BUF_LOOPBACK,
                                     u32LoopbackPeriods);
    if (ret) {
        return ERROR;
    }
    ret = AK_MPI_AI_GetDrvBufPeriods(s32AiDevId, AUDIO_DRV_BUF_LOOPBACK,
                                    &u32LoopbackPeriods);
    if (ret) {
        return ERROR;
    }

    ret = AK_MPI_AI_SetThreadPriority(s32AiDevId, s32AiChnId, AUDIO_THREAD_AI,
                                     s32AiPeriods);
    if (ret) {
        return ERROR;
    }
    ret = AK_MPI_AI_GetThreadPriority(s32AiDevId, s32AiChnId, AUDIO_THREAD_AI,
                                     &s32AiPeriods);
    if (ret) {
        return ERROR;
    }

    ret = AK_MPI_AI_SetThreadPriority(s32AiDevId, s32AiChnId, AUDIO_THREAD_LOOPBACK,
                                     s32LoopbackPeriods);
    if (ret) {
        return ERROR;
    }
    ret = AK_MPI_AI_GetThreadPriority(s32AiDevId, s32AiChnId, AUDIO_THREAD_LOOPBACK,
                                     &s32LoopbackPeriods);
    if (ret) {
        return ERROR;
    }

    /* Step 4: Enable the channel */
    ret = AK_MPI_AI_EnableChn(s32AiDevId, s32AiChnId);
    if (ret) {
        return ERROR;
    }
    AK_FRAME_S stFrame = {0};
    /* Step 5: Get audio data */
    while(1) {
      ret = AK_MPI_AI_GetFrame(s32AiDevId, s32AiChnId, &stFrame, s32TimeOut, 0);
      if (ret) {
        return ERROR;
      }
      // Do something

      /* Step 6: Release audio data */
      ret = AK_MPI_AI_ReleaseFrame(s32AiDevId, s32AiChnId, stFrame, 0);
      if (ret) {
        return ERROR;
      }
    }
    /* Step 7: Disable the channel */
    ret = AK_MPI_AI_DisableChn(s32AiDevId, s32AiChnId);
    if (ret) {
        return ERROR;
    }
    /* Step 8: Disable the device */
    ret = AK_MPI_AI_Disable(s32AiDevId);
    if (ret) {
        return ERROR;
    }
```

&emsp;&emsp;【Paired Interface】

```c
                                      AUDIO_DRV_BUF_TYPE_E enDrvBufType,

```

## AI Module Configuration-File Parameters

The AI module configuration file is `/etc/config/audio_config.ini`. It contains multiple sections, and `AK_MPI_AI_LoadConf` can load parameters from a selected section.

The configuration sections and their use cases are:

| Section name | Scenario |
| --------------- | ------- |
| def_near | Single-microphone capture |
| two_array_near | Two-microphone capture |
| four_array_near | Four-microphone capture |

Each section contains the following configuration parameters:

| Configuration parameter | Description | Value range |
| --------------------- | ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EQ | | |
| eqLoad | Whether to load the EQ module | 0: do not load; 1: load. |
| eqmode | EQ mode | Currently must be `user`. |
| preGain | Total EQ gain | [-12,12] dB; up to two decimal places. |
| bands | Number of equalizers; up to 10 | [0,10]. When greater than 0, use `bands="<#band>, <band0_param>, <band1_param>, ..."`.<br/>Each `bandx_param` is `<type> <freq_Hz> <gain_dB> <Q> <bypass>`.<br/>`type`: hpf/HPF, lpf/LPF, hsf/HSF, lsf/LSF, or pf1/PF1.<br/>`freq_Hz`: 20 <= freq <= sample rate/2/1.2, in Hz.<br/>`gain_dB`: (-32,32), default 0; a gain of 0 is invalid for lsf, hsf, or pf1.<br/>`Q`: 0 <= x.xxx < sample rate/(2*freqs), with x.xxx < 64.000; default 0.<br/>`bypass`: 0 = apply this setting; 1 = ignore it. |
| AEC | | |
| aecEna | Whether AEC is enabled | 0: disabled; 1: enabled. |

| farDigiGain | Output-side digital gain | Range: (0,1]; input 0 has no meaning; default: 1. |

| NR | | |

| AGC | | |
| agcEna | Whether AGC is enabled | 0: disabled; 1: enabled. |
| agcLevel | Target normal-speech amplitude after AGC | Range: (0,1]; default: 0.75; up to two decimal places. |
